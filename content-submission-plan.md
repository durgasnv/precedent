# Content Submission Plan

> This plan is based on the attached **Hindsight Hackathon Content Submission Guide**. The uploaded PDF is a content/submission guide, not an SDK/API integration manual.

## Deliverables
The guide requires:
- one technical article per team member;
- one social post per team member;
- one team video.

Everything should be in English and public/linkable where required.

## Article Workflow

### Step 1 — Generate title candidates
Run the title-generation prompt from the project repository so the coding agent can inspect the actual implementation.

Important constraints from the guide:
- title should focus on the idea/result, not the event;
- do not mention the hackathon in the article title/body;
- mention Hindsight positively;
- keep titles concrete and engineer-focused;
- avoid hype/buzzwords.

### Step 2 — Write the article
Target a technical first-person article centered on one clear engineering story.

For PRECEDENT, possible story:
**How persistent memory prevents engineering teams from repeating failed technical decisions.**

Include:
- hook;
- system architecture;
- one deep technical through-line;
- 2–4 small real code snippets;
- concrete interactions;
- lessons/limitations;
- Hindsight as a major technical theme.

### Step 3 — Add visuals
Capture:
- PRECEDENT UI;
- retain/recall behavior;
- architecture diagram;
- historical decision + changed-assumption demo.

### Step 4 — Publish
Check formatting and required Hindsight/Vectorize references. Publish to a public, linkable developer platform.

### Step 5 — Reddit sharing
Follow the guide's approved subreddit/link-post instructions after publication.

## Article Checklist
- [ ] idea/result-focused title;
- [ ] no hackathon mention in article;
- [ ] concrete opening;
- [ ] real problem;
- [ ] Hindsight integration explained;
- [ ] real code snippet;
- [ ] before/after example;
- [ ] honest limitation/dead end;
- [ ] screenshots/images;
- [ ] public URL.

## Social Post Workflow
After the article is live:
- write a concise developer-focused LinkedIn/X post;
- focus on the real pain and concrete outcome;
- show at least one before/after behavior change;
- mention Hindsight agent memory positively;
- keep the post non-salesy;
- do not frame it around the hackathon;
- include the project GitHub link as required;
- add the article URL according to the guide;
- add the Hindsight repository link in a comment as instructed.

## Video Plan
**Target:** ~3 minutes.

### 0:00–0:30 — Intro
Who we are + one sentence:
“PRECEDENT remembers why engineering ideas failed, so teams know when not to repeat them—and when old decisions deserve another look.”

### 0:30–1:00 — Problem
Show a new proposal with no useful memory and the generic result.

### 1:00–2:30 — Live memory demo
1. Show/retain the historical WebSocket experiment.
2. Submit a similar proposal.
3. Show Hindsight recall.
4. Highlight failure reason and original assumption.
5. Add changed circumstance.
6. Show reassessment.

### 2:30–3:00 — Takeaway
Explain why persistent memory changes the behavior of the agent.

The guide specifically asks the demo to show retain/recall happening live and a before/after moment.
